# feat: MCT (Muscat) official flight data fetcher — HTML parser

## Background

MCT (Muscat International Airport) does not expose a JSON API. However, the airport homepage embeds full flight tables inline in the HTML — no auth, no Referer needed, no JS required.

URL: [https://www.muscatairport.co.om/](<https://www.muscatairport.co.om/>)
Method: GET, User-Agent header required
Returns: 3-day rolling window (yesterday + today + tomorrow)
We only need yesterday's departure count for the daily log.

## What to build

Create .github/scripts/fetch-flights-mct.mjs following the same pattern as log-official-flights.mjs.

### Fetch

GET [https://www.muscatairport.co.om/](<https://www.muscatairport.co.om/>) with User-Agent: Mozilla/5.0

### Parse

* Identify departure tables: look for table headers containing "To" (arrivals use "From")
* Each row has cells: Airlines | To | Flight No | Scheduled date+time | Estimated | Status
* Scheduled date+time format: DD/MM/YYYY HH:MM (e.g. 08/04/2026 00:05)

### Filter

* Parse the scheduled date from each departure row
* Count only rows where date matches yesterday (Asia/Dubai timezone, UTC+4)
* Deduplicate by flight number + scheduled time

### Output

Write to public/verification/flight-log-MCT.json using the same schema as existing airport logs:
{
  "airport": "MCT",
  "entries": \[{ "date": "YYYY-MM-DD", "departures": 152, "arrivals": null, "total": 152,
    "source": "[muscatairport.co.om](<http://muscatairport.co.om>)", "method": "html-parse", "fetchedAt": "...", "success": true }\],
  "lastUpdated": "..."
}

If fetch fails or 0 departures found: write failure entry with success:false and error message.

## Wire into CI

Add a step in .github/workflows/log-flights.yml to run fetch-flights-mct.mjs after existing fetchers.
